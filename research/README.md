# Otxyn Motion — Research Collection

This directory holds the **research and discovery phase** output for Otxyn Motion: an
evidence-based investigation into exceptional web-based motion graphics that will feed
the curated 40-implementation reference library, the agent skill, and the docs.

Research candidates recorded here are **not** approved library entries. They live
separately from `library/manifest.json`, which is the curated 40-entry curation
manifest (built in the 2026-11-03 curation phase by `tools/build_manifest.py`).
Verified statistics for this directory are regenerated by `scripts/gen_data_audit.py`
into [`reports/DATA_AUDIT.md`](reports/DATA_AUDIT.md).

## Terminology

| Term | Meaning |
|---|---|
| `discovered` | Candidate found via search/reference, URL identified. Nothing verified beyond existence of the reference. |
| `inspected` | Source code and/or live demo actually opened and examined. |
| `source inspected` | The actual implementation file(s) (JS/GLSL/CSS/HTML) were read. |
| `browser inspected` | The live demo was loaded in a real browser and visually/behaviourally checked. |
| `interaction tested` | Demo interactions (hover, scroll, pointer) were exercised. |
| `shortlisted` | Passed quality + licensing gauntlet; candidate for the library. |
| `rejected` | Explicitly not suitable (duplicate, low quality, broken, unclear provenance). |
| `blocked` | Evaluation impossible (404 demo, paywall, licence unresolvable). DOIs of failures live in `FAILED_SOURCES.md`. |

# Structure

```text
research/                 # research phase output (below)
library/                  # curation manifest + per-entry reference layer
  manifest.json           #   40-entry roster w/ per-entry licence blocks, route tables,
                          #   verification checklist, OFL font clearances (build script:
                          #   research/tools/build_manifest.py → VALIDATED)
  README.md               # entry-reference folder contract
  <category>/<entry>/reference.md  # PLAIN WORDS → PASS GRAPH → PARAMETERS → ATTRIBUTION
skill/
  SKILL.md                # agent-skill prototype: manifest-first retrieval, licence gate,
                          #   route tables, visual-verification loop
  CRAFT.md                # craft instruction file: timing/composition/refinement doctrine,
                          #   production budgets, craft verification loop (extends SKILL.md §6)
```

## How to read `candidates.json`

One JSON array of candidate objects. Every candidate has a unique ID (`<category>-NNN`),
a category, a description, real URLs only, and an `inspection` block that says exactly
what was verified and when. Missing values use `unknown` / `not_inspected` — never
invented. Scoring rules are documented in `RESEARCH_PLAN.md`.
